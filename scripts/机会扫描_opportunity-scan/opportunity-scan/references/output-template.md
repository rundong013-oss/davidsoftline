# 输出模板：Obsidian 笔记与 JSON 结构

每家公司先整理成一个 JSON，再用 `scripts/render_obsidian.py` 写成 Obsidian 笔记。这样每份笔记格式一致，summary 也能自动汇总。

## 目录

1. 笔记结构
2. JSON 结构
3. 字段写法要求
4. summary.md

---

## 1. 笔记结构

文件：`<vault>/机会扫描/<TICKER>.md`（ticker 按研究系统里的写法，如 `NKE`、`ADS.DE`、`2020.HK`）

```
（frontmatter：ticker、name、scan_date、size、type、setup、analog、watch、tags）

# TICKER 公司名
扫描日期｜机会大小｜机会类型

## 一、基本面
### 年度财务（过去 3 个财年）      收入、收入同比、毛利率、净利率
### 季度财务（过去 3 个季度）      收入、收入同比、毛利率、OPM、净利率
### 业务拆分（公司口径，过去 3 个季度）   一到两层，单元格为"收入（同比）"
### 关键经营数据                    门店数、店效、同店等，公司披露什么写什么
### 小结                            一段话：季度增速与 OPM、Forward PE/PS/净利率、最近财报关注点

## 二、投资机会判断
结论段（set-up、重点变化、如果未来…、类比、类型）
机会大小：大/中/小/— + 理由
### 最近 3 个季度基本面变化         管理层、战略、产品、客群、渠道 × 3 个季度
### 数据来源与缺口

## 历史扫描记录                     每次扫描追加一行，便于看判断的变化
```

## 3. 字段写法要求

- **数值**：比率和增速写小数（0.052 表示 5.2%），脚本按行名自动格式化（行名含"率""同比""增速""占比""OPM"时显示为百分比）。金额写原始数值，单位在 `unit` 里说明。也可以直接写字符串，脚本原样输出。
- **缺失**：写 `null`，显示为"—"。不要编数字。
- **期间**：年度用公司财年（FY2025），季度用财年季度（FY26Q1），与公司披露一致；三张季度表用同一组季度。
- **业务拆分**：只用公司自己披露的口径，层级不超过两层（`level` 1 或 2）。第二层写在所属第一层下面，例如"中国"下的"线上""线下"。公司没披露的拆分不要推算。
- **关键经营数据**：公司披露什么写什么（门店数、店效、坪效、同店、ASP/AUR、折扣率、库存增速、会员数等），没有就整张表留空。
- **五维度表**：每格都要写。没有变化写"无明显变化"，拿不到 transcript 写"缺失"。内容要具体（"关闭 20 家低效门店""CFO 离任"），不要写"持续优化""稳步推进"。
- **结论段**：set-up 一般时，结论段写成"目前 [公司] 的 set-up 一般：……（最近 3 个季度的重点变化）。暂不构成大机会。"，只有在某个类型明显接近时，再用一句话说差在哪里。

## 4. summary.md

`render_obsidian.py` 每次运行都会扫描 `机会扫描/` 下所有带 `机会扫描` 标签的笔记，重建 `summary.md`：

- 顶部一行计数：共几家，大/中/小/set-up 一般各几家
- 汇总表按机会大小排序（大 → 中 → 小 → —），同档内按 ticker 排序
- 列：公司（`[[TICKER]]` 链接到个股笔记）、扫描日期、机会大小、机会类型、set-up、类比、关键观测（`watch`）

summary 只从笔记的 frontmatter 生成，不要手工改；要改判断就改对应公司的 JSON 重新渲染。
